decisions, specifications, and implementation connected. People read and write
the meaning in Markdown. Explicit declarations let tools check its structure
and relationships.

## A shared reference for changing work

When a team revisits a decision, brings someone new into a project, or asks an
AI assistant to make a change, it needs more than a collection of documents.
It needs to know which meaning applies, who accepted it, and how the current
implementation relates to it.

NKF gives that knowledge an explicit structure. A proposal stays a proposal.
An accepted decision has a traceable source. A description of the implementation
can be reviewed against the meaning it is meant to realize.

## A format with clear boundaries

NKF helps people and tools distinguish intent, proposals, accepted meaning,
implementation, and validation. It does not make acceptance decisions for you,
run your project, or prove that your software behaves correctly.

These pages are an introduction. The
[released documentation](https://github.com/NourdApS/Nourd.NKF.Docs)
provides the detailed guides and normative reference. NKF is still pre-stable;
adoption and upgrades require deliberate review.
